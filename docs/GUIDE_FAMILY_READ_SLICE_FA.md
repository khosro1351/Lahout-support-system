# بازبینی نخست راهبر عالی — صفحات خانواده

این مرحله روی شاخه `staging` و بر مبنای `391ec7b435ef1a1b27bc9f023abbec0834784f57` انجام شده است. مبنای `main` همچنان `e529482129e326a4e32c536bb29420b9b06d47fb` است.

## تغییرات

- داشبورد با چهار کارت خلاصه، نوار توجه و چهار ورودی اصلی؛ ورودی خانواده‌ها به فضای مستقل پایش می‌رود.
- پایش خانواده‌ها: پنج فیلتر دائمی، نمودار سطح و حوزه نیاز، وضعیت مشترک در URL، جدول با مرتب‌سازی، اندازه صفحه ۲۰/۵۰/۱۰۰ و بازگشت با حفظ فیلترها.
- پرونده خانواده: شاخص‌ها، پنج حوزه ارزیابی، اعضا، تحقیق، مدارک، حمایت، هشدار، یادداشت مستقل و تاریخچه فشرده.
- صفحات مستقل عضو، نسخه‌های ارزیابی، مأموریت تحقیق و حمایت؛ در این مسیرها عملیات نوشتن برای راهبر اضافه نشده است.
- نسخه انتخابی با مدل و پاسخ‌های تاریخی خودش نمایش داده می‌شود. فرم مشترک قبلی برای نمایش پاسخ‌ها استفاده می‌شود؛ محاسبه امتیاز دوباره در مرورگر انجام نمی‌شود.
- ترکیب هیأت تحقیق، بازدید، ارتباط مدارک، ارتباط حمایت و یادداشت با ذخیره‌سازی افزایشی و تاریخچه غیرقابل‌ویرایش پشتیبانی می‌شود.
- پرداخت‌های دوره‌ای از جدول‌های موجود خوانده می‌شوند. گردش مالی جدید ایجاد نشده است.

## مسیرها

| مسیر | کاربرد |
|---|---|
| `/guide` | صفحه اصلی راهبر |
| `/guide/families` | پایش مستقل خانواده‌ها |
| `/guide/families/:id` | پرونده خانواده |
| `/guide/families/:id/members/:memberId` | جزئیات عضو |
| `/guide/families/:id/assessments` | نسخه‌ها و پاسخ‌های ارزیابی |
| `/guide/families/:id/investigations/:recordId` | تحقیق و هیأت |
| `/guide/families/:id/supports/:recordId` | حمایت و پرداخت‌های مرتبط |

APIهای جدید فقط GET هستند: `/api/v1/oversight/families` و `/api/v1/oversight/families/:id`. هر دو Session و نقش راهبر عالی را در Backend کنترل می‌کنند. دریافت مدرک از Endpoint پیشین با کنترل Scope انجام می‌شود.

## فایل‌ها

- `apps/frontend/src/pages/GuideSlice.tsx` و `GuideSlice.css`: هفت صفحه، کارت‌ها، جزئیات، جدول/نمودار و تاریخچه.
- `App.tsx` و `components/WorkspaceNavigation.tsx`: مسیرها و ناوبری خانواده.
- `pages/AssessmentForm.tsx`: فقط قابل استفاده کردن نمایشگر فیلد موجود؛ فرم سرگروه حفظ شده است.
- `oversight.service.ts` و `oversight.module.ts`: خواندن پایش و ارتباطات خانواده.
- `assessment.service.ts`: نام ثبت‌کننده نسخه از هویت موجود خوانده می‌شود.
- `migrations/0009_family_read_context.sql`: پنج جدول افزایشی، کنترل ارتباط درون خانواده، History/Audit و قفل تغییر/حذف اطلاعات تاریخی.
- `apps/backend/scripts/seed-family-read-dev.ts`: داده ساختگی و قابل تکرار مخصوص Development/Test؛ در production اجرا نمی‌شود.
- `tests/family-read-slice.mjs`: بررسی API، دسترسی، داده مرتبط، فیلترها، بازگشت، خطای دریافت گروه‌ها، نماهای موبایل و تصاویر هفت صفحه؛ در مجموعه `test:guide` اجرا می‌شود.

## اجرای محلی

از ریشه همان Repository، پس از تنظیم `.env` محلی طبق README:

```powershell
pnpm install --frozen-lockfile
pnpm db:migrate
pnpm db:seed:dev
pnpm db:seed:guide:dev
pnpm db:seed:family-read:dev
pnpm typecheck
pnpm build
pnpm test
pnpm test:staging
```

رمز توسعه فقط از متغیر محلی `DEV_SEED_PASSWORD` می‌آید. این سند یا Seed، رمز واقعی ندارد. Seed جدید به رکوردهای آزمایشی موجود متصل می‌شود و رکوردهای نهایی را بازنشانی نمی‌کند.

## محدوده و محدودیت‌های صریح

- داده‌های غایب مانند اعتبار اطلاعات، توانمندی‌ها، مرجع شورا یا ارتباط اختصاصی عضو با حمایت، «ثبت نشده» نشان داده می‌شوند؛ از اطلاعات تصویر استنباط نمی‌شوند.
- ایجاد و ویرایش این اطلاعات توسط سرگروه/شورا، انتخاب هیأت، گردش تصویب حمایت، عملیات پرداخت، اقدام روی هشدار و دیگر نقش‌ها در این مرحله ساخته نشده‌اند.
- تصویرها مرجع چیدمان هستند؛ شمارنده‌ها، نام‌ها و وضعیت‌ها از PostgreSQL می‌آیند و با اعداد نمونه تصویر یکسان نخواهند بود.
- فرم کامل ارزیابی و تاریخچه کامل با بازکردن بخش مربوط دیده می‌شوند تا صفحه اولیه مانند مرجع فشرده بماند.
- فونت و نشان SVG محلی موجود حفظ شده‌اند؛ آیکون‌های برداری هم‌سبک استفاده شده‌اند.
- گزارش‌ها، انتقال خانواده، درخواست‌های دسترسی، Session و مدل امتیازدهی بازطراحی نشده‌اند.
- هیچ سرویس Render یا هزینه میزبانی ایجاد نشده است. این مرحله انتشار Production نیست.

## مقایسه با هفت تصویر مرجع

- داشبورد: ترتیب چهار خلاصه، نوار توجه و شبکه دو در دو ورودی‌ها حفظ شده است؛ رنگ بنفش و نشان نیلوفر محلی باقی مانده‌اند.
- پایش: چهار خلاصه، دو نمودار افقی، پنج فیلتر و جدول مستقل اجرا شده‌اند. لینک گزارش، ورودی جداگانه دارد.
- پرونده: هشت شاخص بالا، بخش اصلی سمت راست و مشخصات/اعضا/یادداشت‌ها سمت چپ قرار دارند.
- عضو: سه ستون سلامت، آموزش و مشخصات، سپس یادداشت، حمایت، مدرک و تاریخچه نمایش داده می‌شوند.
- نسخه‌ها: نوار نسخه جاری، فهرست نسخه‌ها و پنج حوزه نسخه انتخابی؛ پاسخ‌های کامل همان فرم مشترک در بخش بازشدنی هستند.
- تحقیق: مأموریت، بازدید و یافته‌ها در بخش اصلی؛ ترکیب هیأت، مدارک و پیوند شورا در ستون کناری.
- حمایت: خلاصه‌ها، پرداخت‌های دوره‌ای، اسناد و تاریخچه همراه مشخصات و یادداشت‌ها.

چیدمان و زبان بصری مطابق مرجع پیاده شده‌اند، ولی ادعای تطابق پیکسلی نداریم: فونت/آیکون محلی و حجم واقعی متن با تصویر تفاوت دارد. برای نگهداری اطلاعات کامل، ارتفاع بعضی صفحات بیشتر است. متن‌ها و اعداد ساختگی داخل عکس‌ها به داده عملیاتی تبدیل نشده‌اند.

## محدوده قابل توسعه بعدی

صفحه‌بندی، مرتب‌سازی و فیلتر در این نسخه روی مجموعه خانواده‌های فعالِ مجاز در مرورگر انجام می‌شوند. API فقط برای راهبر قابل دسترسی است. انتقال صفحه‌بندی به SQL برای حجم بسیار بزرگ، بهینه‌سازی بسته JavaScript و گردش‌های ثبت اطلاعات توسط نقش‌های دیگر در این مرحله انجام نشده‌اند. Build پیام غیرمسدودکننده بزرگی بسته رابط را گزارش می‌دهد.

## اشکالات یافت‌شده و رفع‌شده

- جابه‌جایی بین حوزه‌های ارزیابی اکنون پارامتر حوزه را جایگزین می‌کند؛ پارامتر تکراری باعث ماندن روی حوزه قبلی نمی‌شود.
- انتخابگر آزمون داشبورد قدیمی با ساختار کارت‌های جدید هماهنگ شد؛ رفتار تأیید/رد دسترسی تغییر نکرد.
- تاریخچه بلند به نمای فشرده و قابل بازشدن تبدیل شد؛ رویدادی حذف نشد.
- نمایش آموزش/سلامت عضو با قواعد نمایش فرم مشترک هماهنگ شد؛ داده پنهان در حالت غیرمشمول، به‌عنوان پاسخ فعال نشان داده نمی‌شود.
- ارتباط مدرک/یادداشت/حمایت با عضو خانواده دیگر در PostgreSQL رد می‌شود.
- خاموش شدن PostgreSQL محلی موجب توقف اجرایی تست شد؛ پس از روشن کردن همان Data Directory، تست‌ها دوباره اجرا شدند؛ Database بازسازی یا Reset نشد.
